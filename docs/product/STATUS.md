## Parallel-session notes (read before starting work)

**Ports.** `:8787` dictation backend (`server.ts`) · `:8788` meetings backend (`meeting.ts`) · `:5175` widget Vite dev server. The two backends are independent processes and share nothing but `@verbatim/core`.

**Lanes — pick one, they don't collide:**

| Lane | Files | Notes |
|---|---|---|
| Dictation / M5 | `apps/backend/src/server.ts`, `packages/core/{pipeline,correction,providers}`, overlay `src/main.ts` | The shipping product. Don't destabilise it for meetings work. |
| Meetings / N-track | `packages/core/src/meetings/*`, `apps/backend/src/meeting.ts`, `apps/widget/meetings.*` | Fully isolated by design. |
| Settings waves | `apps/widget/settings.{html,ts}`, `src-tauri/src/config.rs` | See `docs/product/settings-plan.md`. |
| Rust / native | `apps/widget/src-tauri/src/*` | **Mac only** (below). |

**Known collision hot spots:**
- **`AppConfig` (`src-tauri/src/config.rs`) is THE shared file.** The settings plan adds ~11 fields, meetings will add ~6 (meeting vendor, retention, auto-start, tap allowlist, storage path). `set_config` deserializes the *whole* merged object, so **every new field needs `#[serde(default)]` coverage AND a `Default` entry**, or an existing `settings.json` fails to parse. Land schema fields for both tracks in one commit up front rather than racing.
- `packages/core/src/index.ts` re-exports with `export *`, so **new exports can collide silently**. `correction/prompt.ts` already owns `SYSTEM_PROMPT` / `userMessage` — the meetings module had to rename to `MEETING_SYSTEM_PROMPT` / `meetingUserMessage`. Grep before adding a top-level export.
- `main.rs` was split into 12 modules (13 Aug) precisely so parallel tracks stop fighting over it — add new commands in their own module + one `generate_handler!` line.

**Hard rules:**
- **Rust cannot be compiled in a cloud session.** Anything under `src-tauri/` must be `cargo build` / `npm run widget`-verified on the Mac. `rustfmt` is a usable *syntax* gate in the cloud, nothing more.
- **Network:** cloud sessions cannot reach `api.pyai.com` (proxy 403) and the device bridge has no network at all. **PyAI probes must be run from the Mac terminal** — `experiments/scripts/probe_hear_caps.py` is the current one.
- **Secrets:** `.env` holds a live key. It must never enter this project, a chat, or a commit. The leaked PyAI test key still needs rotating before M6.

To improve: capture the raw stream with `PYAI_STT_DEBUG=1 npm run backend`, save a few `[hear]` lines, and tune `mergeOverlap` / add a fixture in `packages/core/src/pipeline.test.ts`.

- **F10 — ✅ ANSWERED (13 Aug 2026, openapi probe).** The finalize control message is **`{"type":"commit"}`** (the literal text frame `EOF` is an equivalent flush; closing the socket also flushes). `endpointing_ms` is configurable at connect or mid-session. Also: **`protocol=pyai-hear-v1`** selects the published frame names — omitting it keeps the legacy `fusion-v0` names (`transcript.partial`, `session.created`), which is what the current adapter reads. **Close F10 in `docs/research/pyai-api-findings.md` and consider adopting `commit`.**
