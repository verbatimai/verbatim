# M5.7 — Dogfood Exit Plan

Phase 5.7 is the two-week internal dogfood that gates Milestone M5 ("Quality & polish — daily-driver"). Everything in M5 has landed in the packaged `Verbatim.app`; this phase proves it holds up under real daily use before we cut M6 (public v1.0).

## What dogfood proves

Dogfood is not a test suite — it is the Saaslabs team using Verbatim as their *primary* dictation tool for real work, on real vendors, for two weeks. It exists to surface the failures that only appear in the wild: a dropped socket mid-sentence, a proper noun mangled, an over-correction that eats a real word, focus stolen at the wrong moment.

**Exit bar:** two full weeks with **no open blocking bugs**, and latency/accuracy that read as "instant" in normal use (see the perf targets below). If a blocker is found, its clock does not reset the whole two weeks, but the blocker must be fixed and re-verified before sign-off.

> Run dogfood on a **healthy vendor**. PyAI is our default provider but is currently 404-ing vendor-side, so do not gate the milestone on it. Use OpenAI / Anthropic / Deepgram.

## Setup checklist

The cohort is the Saaslabs team. Spread provider combos so all three healthy vendors get real hours:

- [ ] Assign each person a primary vendor so coverage is roughly even across **OpenAI**, **Anthropic**, and **Deepgram**.
- [ ] Each person adds **~5 real vocabulary terms** to the Settings term list — actual names, products, jargon they say daily (this is what proves custom-vocab improves proper-noun accuracy).
- [ ] Each person adds **a couple of snippets** (text-expansion) they'll genuinely use.
- [ ] Toggle **telemetry ON** in Settings. Transport is parked (NoopSink) — nothing leaves the device; the perf numbers are read locally off the Mac.
- [ ] Confirm the app launches, the backend sidecar comes up, and a first dictation lands cleanly before day 1.

**Filing a bug.** Every report includes: exact repro steps; vendor combo; target app (Slack, Notes, VS Code, etc.); **what was said vs. what was inserted**; and the attached `errors.log` path. Missing repro or vendor combo makes a report un-actionable — do not skip them.

## Daily / weekly protocol

Use Verbatim as your primary dictation tool for messages, docs, and code comments. Passive use is the point, but each person must also *deliberately* exercise these each week:

- [ ] **Rotate formatting modes:** prose, message, code, and raw — use each on work that suits it.
- [ ] **Test revert-to-raw:** force an over-correction, then undo back to the raw transcript and confirm it restores what you actually said.
- [ ] **Test reliability at least once:** toggle Wi-Fi off mid-dictation. Confirm it either auto-reconnects (retry after a dropped socket or a vendor 429) or degrades cleanly — and that the **raw transcript is still injectable** so no dictation is lost.
- [ ] **Test custom vocab + snippets** in real sentences, not just once — confirm terms stick and snippets expand in the target apps you actually use.

## Triage rubric

**BLOCKING** (must be fixed before exit):
- Lost dictation — audio spoken, nothing (raw or corrected) recoverable.
- Wrong text injected into a field (not just a bad correction — text landing that was never said, or landing in the wrong place).
- Focus stolen from the user's active field.
- Crash / hang of the app or sidecar.
- A **password / secure field not refused** — Verbatim must never inject into one.

**NON-BLOCKING** (log, don't gate): cosmetic UI, a single mis-corrected word, mode picking slightly wrong punctuation, snippet edge cases, latency that's acceptable but not crisp. These feed the polish backlog; they do not stop M5.

## Perf pass (F9 / F10)

Run this on the Mac, eyeballed — no metrics leave the device.

- [ ] **F9 correction latency:** dictate normally and watch the self-correction settle. It should read as **"< ~1s after you pause."** If corrections visibly lag behind speech, log it. (The backend now emits `sttLatencyMs` / `correctionLatencyMs` / `formatLatencyMs` on the telemetry `session_finalize` event — read them off the local log when telemetry is on for exact numbers.)
- [ ] **F9 memory:** keep a single session live for **~30 minutes** and watch memory in Activity Monitor. It should stay **steady** — a continuous climb is a leak and is a blocker.
- [ ] **F10 finalize under reconnect:** start an utterance, force a reconnect (Wi-Fi toggle or kill the socket), and confirm end-of-utterance **finalize still fires cleanly** and the final text is correct. Verify across each vendor in the cohort.

## Exit sign-off

M5 is done — and we move to M6 — only when **all** of these are green:

- [ ] Two weeks of primary-tool dogfood completed across the cohort.
- [ ] **Zero open blocking bugs** (all found blockers fixed and re-verified).
- [ ] Acceptance matrix complete for every in-use vendor, all blocking-relevant columns Pass.
- [ ] At least one non-English pass Passed on Deepgram or OpenAI.
- [ ] F9 latency reads "instant," memory steady over 30 min; F10 finalize solid under forced reconnect on every vendor.
- [ ] Reliability confirmed: a dropped socket or vendor 429 never loses a dictation (raw transcript always recoverable).
- [ ] Password/secure fields refused, everywhere tested.
- [ ] **Leaked PyAI test key rotation scheduled or done** — tracked as an **M6 security gate** (not an M5 blocker, but it must be on the M6 board before public release).

Sign-off is a named owner checking every box above, not a vibe. When the list is all-green, declare M5 complete and open M6.
