# M4 · Phase 4.4 — Finish the Deepgram STT Adapter — Implementation Plan

**Parent:** `m4-tasks.md` (Phase 4.4) · **Architecture:** `../architecture/vendor-transport.md`, `../architecture/vendor-apis.md` · **Package:** `packages/core` (vendor-neutral, cloud-testable).

**Goal:** take `providers/deepgram.stt.ts` from ~60% to done — env-overridable endpoint/model, proper endpointing so utterances segment cleanly, robust `speech_final` + `UtteranceEnd` → `endpoint` mapping, a batch path for the finalize step (parity with PyAI/OpenAI), and a mock-server integration test green in the cloud. This is the **last remaining vendor adapter**; once it lands, all three of Deepgram/OpenAI/Anthropic are behind the existing interfaces.

---

## Current state (grounded in the code)

`providers/deepgram.stt.ts` already implements the shape and most of the mapping:

- `DeepgramSTT implements STTProvider` — `id="deepgram"`, `requiredKeys=["DEEPGRAM_API_KEY"]`, `audio={16000, pcm_s16le, 1}`. Registered in `providers/registry.ts` (`deepgram: () => new DeepgramSTT()`).
- `startSession` opens `wss://api.deepgram.com/v1/listen?encoding=linear16&sample_rate=16000&channels=1&interim_results=true&vad_events=true[&language=…]` with a Node-`ws` header `Authorization: Token <key>`.
- `DeepgramSession` derives our contract from interim/final: accumulated finalized text → `stableText`; current interim → `activeText`. Handles `is_final` (lock into stable) and `UtteranceEnd` (emit `final`, `endpoint:true`, reset). `finalize()` sends `{type:"CloseStream"}`; `sendAudio` forwards frames.

**What's missing / to fix (the 40%):**

1. **No endpoint/model config is overridable** → the socket URL is a hard constant, so it can't be pointed at a mock server (that's why there are **no tests**). OpenAI's adapter solved this with `OPENAI_REALTIME_WS_URL`/`OPENAI_STT_MODEL` read at call time; mirror it.
2. **Endpointing params absent** — URL lacks `model`, `smart_format`, `punctuate`, `endpointing`, and `utterance_end_ms`. Without `utterance_end_ms`, the `UtteranceEnd` message never fires; without `endpointing`, `speech_final` won't be set.
3. **`speech_final` unhandled** — Deepgram marks the end of a spoken segment on a `Results` message with `speech_final:true` (endpointing), separately from the `UtteranceEnd` message (gap-based, `utterance_end_ms`). Only `UtteranceEnd` is handled today; `speech_final` should also close a segment, and the two must be **de-duplicated** so one segment doesn't emit two finals.
4. **No `transcribeBatch`** — PyAI and OpenAI both implement it; the product finalize path (M2: "batch-transcribe the full audio on stop") uses it for the authoritative transcript. Deepgram needs it for parity (prerecorded API).
5. **No integration test** — needs a mock-WS-server test mirroring `openai.stt.integration.test.ts` / `pyai.integration.test.ts`.

**Transport — already decided, simplifies this phase:** per `vendor-transport.md` (4.0), streaming STT runs in the **app-managed Node sidecar** (a "secure backend"), *not* the webview. So the existing Node-`ws` `Authorization` header is correct — the old "won't work from a browser" worry is moot (same reasoning as `openai.stt.ts`). **No webview/subprotocol-token work is needed.**

---

## Approach & key decisions

1. **Mirror the OpenAI adapter's env-override pattern** — `DEEPGRAM_WS_URL` and `DEEPGRAM_STT_MODEL` read at call time. Unblocks the mock test and the 4.7 model dropdown; production uses the defaults.
2. **Turn on real endpointing** — add `model` (default `nova-2`, env-overridable), `smart_format=true`, `punctuate=true`, `endpointing=300` (ms of silence → `speech_final`), and `utterance_end_ms=1000` (gap → `UtteranceEnd`). Keep `interim_results=true` and `vad_events=true`.
3. **One segment boundary, two triggers, de-duplicated** — treat both `speech_final:true` (on a `Results` message) and the `UtteranceEnd` message as "close the current segment": emit a single `final` with `endpoint:true`, then reset. Guard with a per-utterance "already finalized" flag so whichever arrives second is ignored.
4. **Add `transcribeBatch`** (Deepgram prerecorded `POST /v1/listen`) for finalize parity with PyAI/OpenAI. `DEEPGRAM_BASE` override for the mock.
5. **Robustness: KeepAlive** — Deepgram closes an idle socket after ~10–12 s with no audio. Dictation streams continuously while recording, but add a lightweight `{type:"KeepAlive"}` heartbeat during silence gaps to be safe.

## Step-by-step

### 1. Env-overridable endpoint + model (testability)

```ts
const DEFAULT_WS_URL = "wss://api.deepgram.com/v1/listen";
const DEFAULT_MODEL = "nova-2"; // vendor-apis.md; env-overridable

// in startSession(), read at call time:
const base = process.env.DEEPGRAM_WS_URL ?? DEFAULT_WS_URL;
const model = process.env.DEEPGRAM_STT_MODEL ?? DEFAULT_MODEL;
```

### 2. Build the query with endpointing

```ts
const q = new URLSearchParams({
  model,
  encoding: "linear16",
  sample_rate: String(this.audio.sampleRate),
  channels: "1",
  interim_results: "true",
  vad_events: "true",
  smart_format: "true",
  punctuate: "true",
  endpointing: "300",        // ms silence → speech_final on the Results msg
  utterance_end_ms: "1000",  // gap → a separate UtteranceEnd msg (needs interim_results)
});
if (cfg.language) q.set("language", cfg.language);
const ws = new WebSocket(`${base}?${q.toString()}`, {
  headers: { Authorization: `Token ${cfg.apiKey}` },
});
```

### 3. Segment mapping with `speech_final` + `UtteranceEnd`, de-duplicated

Replace `onMessage` so a segment closes on **either** trigger, once:

```ts
private stable = "";
private utteranceId = "u0";
private uCounter = 0;
private finalizedThisSegment = false; // dedup guard

private closeSegment() {
  if (this.finalizedThisSegment && !this.stable) return; // nothing new to finalize
  const text = this.stable.trim();
  this.tcb?.({ type: "final", utteranceId: this.utteranceId,
    text, stableText: text, activeText: "", endpoint: true });
  this.stable = "";
  this.finalizedThisSegment = true;
  this.utteranceId = `u${++this.uCounter}`;
}

private onMessage(raw: string) {
  if (process.env.DEEPGRAM_STT_DEBUG) console.error("[deepgram-stt] " + raw);
  const m = JSON.parse(raw);

  if (m.type === "UtteranceEnd") { this.closeSegment(); return; }
  if (m.type !== "Results") return; // ignore Metadata/SpeechStarted/etc.

  const alt = m.channel?.alternatives?.[0];
  const piece = alt?.transcript ?? "";
  if (m.is_final) {
    if (piece) { this.stable = (this.stable + " " + piece).trim(); this.finalizedThisSegment = false; }
    this.emitPartial("");                 // lock interim into stable
    if (m.speech_final) this.closeSegment(); // endpointing boundary
  } else {
    this.finalizedThisSegment = false;
    this.emitPartial(piece);              // interim tail = active
  }
}

private emitPartial(active: string) {
  this.tcb?.({ type: "partial", utteranceId: this.utteranceId,
    text: (this.stable + " " + active).trim(), stableText: this.stable, activeText: active });
}
```

> The guard makes `speech_final` and a following `UtteranceEnd` (or vice-versa) yield **one** `final` per segment.

### 4. `finalize()` — flush then close

```ts
async finalize() {
  if (this.ws.readyState === WebSocket.OPEN) {
    this.ws.send(JSON.stringify({ type: "Finalize" }));   // flush pending audio → last final
    await new Promise((r) => setTimeout(r, 200));
    this.ws.send(JSON.stringify({ type: "CloseStream" })); // then close
  }
}
```

### 5. `transcribeBatch` — finalize parity (Deepgram prerecorded)

```ts
async transcribeBatch(pcm: Uint8Array, cfg: { apiKey: string; sampleRate?: number }): Promise<string> {
  const base = process.env.DEEPGRAM_BASE ?? "https://api.deepgram.com/v1";
  const model = process.env.DEEPGRAM_STT_MODEL ?? DEFAULT_MODEL;
  const wav = pcmToWav(pcm, cfg.sampleRate ?? this.audio.sampleRate, 1); // reuse ../audio/wav
  const q = new URLSearchParams({ model, smart_format: "true", punctuate: "true" });
  const res = await fetch(`${base}/listen?${q}`, {
    method: "POST",
    headers: { Authorization: `Token ${cfg.apiKey}`, "Content-Type": "audio/wav" },
    body: wav,
  });
  if (!res.ok) throw new Error(`Deepgram transcribe ${res.status}: ${await res.text()}`);
  const body = (await res.json()) as any;
  return String(body.results?.channels?.[0]?.alternatives?.[0]?.transcript ?? "").trim();
}
```

### 6. Integration test — `providers/deepgram.stt.integration.test.ts`

Mirror `openai.stt.integration.test.ts`: a mock `WebSocketServer` that captures the `Authorization` header + the query string, then scripts a realistic message sequence, plus a mock HTTP server for `transcribeBatch`.

- **Streaming test:** point `DEEPGRAM_WS_URL` at the mock. Assert: header `Token <key>`; query contains `endpointing`, `utterance_end_ms`, `smart_format`, `model`. Drive: interim `{type:"Results", is_final:false, channel:{alternatives:[{transcript:"hello"}]}}` → interim → `{is_final:true, speech_final:false, transcript:"hello world"}` → `{type:"UtteranceEnd"}`. Assert: last partial `activeText:"hello"`, `stableText:""`; after is_final `stableText:"hello world"`; exactly **one** `final` with `endpoint:true` and `text:"hello world"` (dedup — `speech_final` case tested in a second scenario).
- **speech_final scenario:** `{is_final:true, speech_final:true, transcript:"one two"}` with **no** following `UtteranceEnd` → one `final`, `endpoint:true`. And the reverse (both fire) → still one.
- **Batch test:** mock `POST /v1/listen` returning `{results:{channels:[{alternatives:[{transcript:"clean batch"}]}]}}`; assert `Authorization: Token …` and returned text.

`deepgram` is already registered and `requiredKeys=["DEEPGRAM_API_KEY"]`; `assertKeys`/`assertCorrectionKeys`/`capabilityErrors` (4.1) already cover it.

## Risks / gotchas

- **Double endpoint** — `speech_final` and `UtteranceEnd` can both fire for one segment; the `finalizedThisSegment` guard prevents a duplicate `final`. Cover both orders in tests.
- **`utterance_end_ms` requires `interim_results=true`** (already on) — without it, `UtteranceEnd` never arrives.
- **Idle-socket close (~10–12 s)** — send `{type:"KeepAlive"}` during silence if the session can idle; not critical while continuously recording.
- **Model availability** — confirm the `model` id (`nova-2` vs `nova-3`) against `vendor-apis.md`; it's env-overridable so it's a config, not a code, change.
- **Sample-rate match** — the capture side must feed 16 kHz pcm16 (the adapter's declared `audio`); the 4.8 sidecar wiring must respect each provider's declared rate (Deepgram 16 k vs OpenAI 24 k).
- **Batch content-type** — sending WAV with `Content-Type: audio/wav` is simplest; raw linear16 also works but needs `encoding`/`sample_rate` query params. WAV avoids that.
