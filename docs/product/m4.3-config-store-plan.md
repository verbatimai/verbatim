# M4 · Phase 4.3 — Config Store + Keychain (backbone) — Implementation Plan

**Parent:** `m4-tasks.md` (Phase 4.3) · **Architecture:** `../architecture/desktop-app-windows.md`, `../architecture/vendor-transport.md` · **App:** `apps/widget` (Tauri v2, now branded **Verbatim**).

**Goal:** one Rust persistence layer that is the widget's single source of truth. Consolidate today's scattered state — API keys already in the Keychain, the hotkey in a standalone file, vendor/language selection nowhere-persisted — into (a) a **prefs store** (`tauri-plugin-store`) that persists `AppSettings` + widget-only prefs and broadcasts a **`config-changed`** event, and (b) a **per-vendor keychain** layer. This is the seam 4.7 (settings UI), 4.8 (sidecar key hand-off), and live re-config all plug into. Mostly consolidation — the keychain half already works.

---

## Current state (grounded in the code)

- **Keychain BYOK exists** (`src-tauri/src/main.rs`): `key_save` / `key_get` / `key_has` / `key_delete` / `key_save_clipboard`, all keyed by an `account` string (the env-var name), under `const KEYCHAIN_SERVICE: &str = "co.saaslabs.verbatim"`.
- **Hotkey persists to a file** — `hotkey_config_path()` → `<app_config_dir>/hotkey`; `load_hotkey_id()` / `save_hotkey_id()`; `set_toggle_hotkey` swaps the live registration and writes the file; `CURRENT_TOGGLE` holds the registered `Shortcut`. Startup reads `load_hotkey_id()`.
- **Vendor/language selection has no persistence.** The core type is shipped in `packages/core/src/settings.ts`:
  ```ts
  interface AppSettings { sttProvider: "pyai"|"deepgram"|"openai";
                          correctionProvider: "pyai"|"openai"|"anthropic";
                          language: string; }
  const DEFAULT_SETTINGS = { sttProvider: "pyai", correctionProvider: "pyai", language: "en" };
  ```
  `resolveProviders()` / `capabilityErrors()` / `assertCapability()` consume it; nothing writes it to disk yet.
- **No prefs store plugin.** `Cargo.toml` has `tauri`, `tauri-plugin-global-shortcut`, `keyring`, `serde`, `serde_json`, `arboard`, `enigo`, `tauri-nspanel` — **no `tauri-plugin-store`**.
- **Commands** are registered in `invoke_handler![…]`; custom commands are directly invokable (Tauri v2 capabilities gate *plugin* IPC, not our own commands).

---

## Approach & key decisions

1. **`tauri-plugin-store`, used from Rust only.** We expose our own typed `get_config` / `set_config` commands that read/write the store internally. The webview never calls the store plugin directly → **no capability change needed** (custom commands aren't permission-gated). If the frontend ever needs direct JS store access, add `"store:default"` then.
2. **One JSON object, camelCase, superset of `AppSettings`.** Persist a single `config` key whose shape matches the TS `AppSettings` **plus** widget-only prefs, so the same JSON round-trips both sides:
   ```jsonc
   { "sttProvider":"pyai", "correctionProvider":"pyai", "language":"en",
     "hotkey":"alt-space", "dockIcon":false }
   ```
   `sttProvider`/`correctionProvider`/`language` are exactly the core `AppSettings`; `hotkey`/`dockIcon` are widget-only (not in the core type — that stays as shipped in 4.1).
3. **`config-changed` on every write.** `set_config` emits it (payload = the new config) so the overlay/pipeline refresh live in 4.7/4.8.
4. **Fold the hotkey into the store; migrate the legacy file.** `set_toggle_hotkey` becomes a thin wrapper over `set_config({hotkey})`; startup reads the hotkey from the store; on first run we seed the store from the old `<app_config_dir>/hotkey` file (back-compat, nobody loses their hotkey).
5. **Per-vendor keychain wrappers.** Add `set_key`/`has_key`/`delete_key` keyed by vendor id (`pyai`→`PYAI_API_KEY`, …), mirroring the registry's `requiredKeys`. Keep the existing `key_*` commands (current UI still uses them) — the new ones are the forward API for 4.7.
6. **No frontend change required in 4.3.** It's a Rust backbone; `set_toggle_hotkey` keeps working (now store-backed). The settings UI wiring is 4.7.

### 3. `main.rs` — the config type + store helpers

```rust
use serde::{Deserialize, Serialize};

// Persisted widget config. Superset of core `AppSettings` (sttProvider/correctionProvider/
// language) + widget-only prefs (hotkey/dockIcon). camelCase so the JSON matches AppSettings.
#[derive(Serialize, Deserialize, Clone, Debug)]
#[serde(rename_all = "camelCase", default)]
struct AppConfig {
    stt_provider: String,        // "pyai" | "deepgram" | "openai"
    correction_provider: String, // "pyai" | "openai" | "anthropic"
    language: String,            // BCP-47, default "en"
    hotkey: String,              // preset id or captured accelerator
    dock_icon: bool,
}

impl Default for AppConfig {
    fn default() -> Self {
        Self {
            stt_provider: "pyai".into(),
            correction_provider: "pyai".into(),
            language: "en".into(),
            hotkey: "alt-space".into(),
            dock_icon: false,
        }
    }
}

const STORE_FILE: &str = "settings.json";
const CONFIG_KEY: &str = "config";

fn read_config(app: &tauri::AppHandle) -> AppConfig {
    use tauri_plugin_store::StoreExt;
    let store = match app.store(STORE_FILE) { Ok(s) => s, Err(_) => return AppConfig::default() };
    store.get(CONFIG_KEY)
        .and_then(|v| serde_json::from_value(v).ok())
        .unwrap_or_default()
}

fn write_config(app: &tauri::AppHandle, cfg: &AppConfig) -> Result<(), String> {
    use tauri_plugin_store::StoreExt;
    let store = app.store(STORE_FILE).map_err(|e| e.to_string())?;
    store.set(CONFIG_KEY, serde_json::to_value(cfg).map_err(|e| e.to_string())?);
    store.save().map_err(|e| e.to_string())
}
```

> **Verify:** `tauri-plugin-store` v2 API — `AppHandle::store(path) -> Result<Arc<Store>>` (via `StoreExt`), `store.get(k) -> Option<Value>`, `store.set(k, v)`, `store.save()`. Method shapes shifted across 2.x point releases; pin the version and let `cargo build` confirm.

### 4. `main.rs` — the commands + `config-changed`

```rust
#[tauri::command]
fn get_config(app: tauri::AppHandle) -> AppConfig { read_config(&app) }

#[tauri::command]
fn set_config(app: tauri::AppHandle, patch: serde_json::Value) -> Result<AppConfig, String> {
    // shallow-merge the patch over the current config
    let mut cur = serde_json::to_value(read_config(&app)).map_err(|e| e.to_string())?;
    if let (Some(base), Some(p)) = (cur.as_object_mut(), patch.as_object()) {
        for (k, v) in p { base.insert(k.clone(), v.clone()); }
    }
    let next: AppConfig = serde_json::from_value(cur).map_err(|e| e.to_string())?;
    write_config(&app, &next)?;

    // Side effect: if the hotkey changed, re-register it live.
    #[cfg(desktop)]
    { let _ = apply_hotkey(&app, &next.hotkey); }

    let _ = app.emit("config-changed", &next); // Emitter is already imported
    Ok(next)
}
```

### 5. `main.rs` — fold the hotkey into config + migrate the legacy file

Extract the live-swap out of `set_toggle_hotkey` into a reusable `apply_hotkey`, make `set_toggle_hotkey` a thin wrapper, and read the hotkey from the store at startup:

```rust
#[cfg(desktop)]
fn apply_hotkey(app: &tauri::AppHandle, id: &str) -> Result<(), String> {
    use tauri_plugin_global_shortcut::GlobalShortcutExt;
    let sc = preset_shortcut(id).ok_or_else(|| format!("unknown hotkey: {id}"))?;
    let gs = app.global_shortcut();
    if let Some(old) = CURRENT_TOGGLE.lock().unwrap().take() { let _ = gs.unregister(old); }
    gs.register(sc).map_err(|e| e.to_string())?;
    *CURRENT_TOGGLE.lock().unwrap() = Some(sc);
    Ok(())
}

#[tauri::command]
fn set_toggle_hotkey(app: tauri::AppHandle, id: String) -> Result<(), String> {
    // now store-backed: set_config re-registers + persists + emits config-changed
    set_config(app, serde_json::json!({ "hotkey": id })).map(|_| ())
}

// One-time seed: if the store has no config yet, create it from defaults, importing the
// old <app_config_dir>/hotkey file if present so existing users keep their choice.
fn migrate_legacy_config(app: &tauri::AppHandle) {
    use tauri_plugin_store::StoreExt;
    let Ok(store) = app.store(STORE_FILE) else { return };
    if store.get(CONFIG_KEY).is_some() { return; }
    let mut cfg = AppConfig::default();
    if let Some(p) = hotkey_config_path(app) {
        if let Ok(s) = std::fs::read_to_string(p) {
            let id = s.trim().to_string();
            if !id.is_empty() { cfg.hotkey = id; }
        }
    }
    let _ = write_config(app, &cfg);
}
```

In `setup()`, before registering the shortcut, replace the `load_hotkey_id()` read:

```rust
migrate_legacy_config(app.handle());
let hotkey_id = read_config(app.handle()).hotkey;      // was: load_hotkey_id(app.handle())
let toggle = preset_shortcut(&hotkey_id)
    .unwrap_or_else(|| Shortcut::new(Some(Modifiers::ALT), Code::Space));
*CURRENT_TOGGLE.lock().unwrap() = Some(toggle);
```

`load_hotkey_id` / `save_hotkey_id` / `get_toggle_hotkey` can stay for one release (or be removed once the UI reads `get_config`); mark them deprecated.

### 6. `main.rs` — per-vendor keychain wrappers

```rust
// Vendor id → its Keychain account (env-var) name. MUST stay in sync with each
// provider's requiredKeys in packages/core (providers/registry.ts, correction/registry.ts).
fn vendor_key_name(vendor: &str) -> Option<&'static str> {
    match vendor {
        "pyai" => Some("PYAI_API_KEY"),
        "deepgram" => Some("DEEPGRAM_API_KEY"),
        "openai" => Some("OPENAI_API_KEY"),
        "anthropic" => Some("ANTHROPIC_API_KEY"),
        _ => None,
    }
}

#[tauri::command]
fn set_key(vendor: String, secret: String) -> Result<(), String> {
    let acct = vendor_key_name(&vendor).ok_or_else(|| format!("unknown vendor: {vendor}"))?;
    keyring::Entry::new(KEYCHAIN_SERVICE, acct)
        .and_then(|e| e.set_password(&secret)).map_err(|e| e.to_string())
}

#[tauri::command]
fn has_key(vendor: String) -> bool {
    vendor_key_name(&vendor)
        .map(|acct| keyring::Entry::new(KEYCHAIN_SERVICE, acct)
            .and_then(|e| e.get_password()).is_ok())
        .unwrap_or(false)
}

#[tauri::command]
fn delete_key(vendor: String) -> Result<(), String> {
    let acct = vendor_key_name(&vendor).ok_or_else(|| format!("unknown vendor: {vendor}"))?;
    match keyring::Entry::new(KEYCHAIN_SERVICE, acct).and_then(|e| e.delete_credential()) {
        Ok(()) | Err(keyring::Error::NoEntry) => Ok(()),
        Err(e) => Err(e.to_string()),
    }
}
```

## Acceptance criteria + on-Mac verification

`cargo build` (in `src-tauri/`) must pass; then `npm run widget`.

1. **Config round-trips.** `invoke("get_config")` returns defaults on first run; `invoke("set_config", {patch:{language:"fr"}})` returns the merged config and `get_config` reflects it after relaunch.
2. **`config-changed` fires.** A listener on `config-changed` receives the new config object when `set_config` runs.
3. **Keys persist across restarts.** `set_key("pyai", …)` → quit → relaunch → `has_key("pyai")` is `true`.
4. **Hotkey migrated + still live.** With an existing `<app_config_dir>/hotkey`, first launch seeds `settings.json` with that id; changing the hotkey (via `set_toggle_hotkey` or `set_config`) re-registers it live and survives relaunch.

---

## Risks / gotchas

- **`tauri-plugin-store` v2 API drift** — the `store()`/`get`/`set`/`save` shapes vary across 2.x; pin the version and confirm with `cargo build` (see note in step 3).
- **Plugin init order** — register `tauri_plugin_store` on the builder **before** `setup()` uses `app.store(...)`. Plugins initialize during build, so setup-time access is fine.
- **serde shape** — `#[serde(rename_all = "camelCase", default)]` + a `Default` impl so partial/old JSON deserializes without error; unknown extra keys are ignored.
- **Vendor→key map drift** — `vendor_key_name` mirrors the TS `requiredKeys`; keep them in sync (same hazard as `preset_shortcut` ↔ the UI's `HOTKEYS`). A shared source is a later cleanup.
- **Migration idempotency** — `migrate_legacy_config` only seeds when no `config` key exists, so it runs once and never clobbers user changes.
- **Don't log secrets** — the keychain wrappers must never print the secret (existing `key_*` already follow this).
